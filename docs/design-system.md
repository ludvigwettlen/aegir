# Aegir design system

The Lime Glass direction is being introduced one section at a time. The [Paper Tasks sketch](https://app.paper.design/file/01M35BFSHJZGNPY821ZEJG3MQ2/p-1-0/BR-0) defines the compact layout. The third image in `design/concepts/03-lime-glass.png` defines the color and atmosphere. The workspace (sidebar, Tasks, groups and threads, Routines) is fully on Lime Glass; Memory and Settings still use some legacy styles from `light.scss`. The layouts follow the sketch canvas agreed in September 2026.

## Foundations

The source of truth for new semantic values is `src/ui/design-system/tokens.scss`. Use tokens in component styles rather than repeating hex values. Existing blue styles in `light.scss` remain until their sections are migrated.

| Role | Token | Value | Use |
| --- | --- | --- | --- |
| Canvas | `--ds-color-canvas` | `#fcfdf9` | Quiet app ground |
| Surface | `--ds-color-surface` | `#ffffff` | Opaque controls |
| Glass | `--ds-color-glass` | `#ffffffd9` | Panels over ambient color |
| Ink | `--ds-color-ink` | `#1f2b1d` | Primary text and icons |
| Muted | `--ds-color-muted` | `#596753` | Secondary text and timestamps |
| Line | `--ds-color-line` | `#dfe7d8` | Borders and dividers |
| Lime | `--ds-color-lime` | `#a9e929` | Primary action and active state |
| Lime soft | `--ds-color-lime-soft` | `#edf8d2` | User messages and subtle selection |
| Lime ink | `--ds-color-lime-ink` | `#42622c` | Text on pale lime surfaces |
| Lemon | `--ds-color-lemon` | `#ffe95e` | Ambient light and sparing emphasis |
| Link | `--ds-color-link` | `#366d36` | Source links inside chat bubbles |

Typography is selected in Settings → Fonts. `--ds-font-system` covers the app's headings, navigation, controls, conversations, and splash-screen name; `--ds-font-editor` covers Markdown document content, including its headings. Both default to Inter. The body and heading tokens alias the system font except inside document prose. Editor toolbars keep the system font, while code and logs retain monospace. Fonts are bundled locally through Fontsource and work offline. The chat uses 13 px body text at 1.6 line-height. The small labels in the compact pane must still be readable at the app's 900 px minimum width.

Ambient color belongs behind the content. Only translucent surfaces receive backdrop blur. Never blur text, icons, or the message content itself. Use a 1 px boundary to keep each glass panel legible when the background glow changes. Motion must respect reduced-motion preferences.

## Shared primitives

`src/ui/design-system/primitives.tsx` adapts the Fragments components already in use. Import these Aegir exports in product views instead of importing the same components directly from `@usefragments/ui`. Their Fragments foundations retain semantics, keyboard behavior, and core sizing; `primitives.scss` applies our tokens and visual states. `ThemeProvider` remains a library integration, not a product component. The chat `Prompt` is adapted through `ChatComposer` below.

### `Button`

Use for actions, not navigation labels or passive status. Its anatomy is a label with an optional leading or trailing icon; icon-only buttons require an accessible name. Default solid/accent is the lime primary action. Use `outline` for secondary actions, `ghost` in dense rows and toolbars, and `link` for tertiary actions. Keep one dominant solid action in an action group. The wrapper retains Fragments' `size`, `icon`, `fullWidth`, disabled, and keyboard behavior. Lime, surface, ink, border, and disabled tokens define its states; hover and focus must remain visible.

### `Badge`

Use for short, non-interactive counts, categories, or status. The label is required; an optional dot reinforces status but never replaces text. `neutral` is ordinary metadata, `info`/`accent` are lime emphasis, `success` and `danger` are outcome states, and `warning` is lemon. `soft` is the default pill; use `outline` only when a filled badge would compete with nearby content. Preserve a readable label at small size and request status announcement only when a live change needs it.

### `Card`

Use to group related content with a clear boundary. `solid` is an opaque elevated surface, `outline` is a milky glass panel, and `soft` is a quiet lime-tinted grouping. The border and radius come from tokens; only glass receives backdrop blur. Use `padding="none"` when the contents own their insets or include an internal divider. Keep headings and interactive elements semantic inside the card; a card is not automatically clickable.

### `ToggleGroup`

Use for a small set of mutually exclusive views or filters. The current workspace switcher is the first use. The group contains labeled items, with the selected item on a soft lime surface; hover and keyboard focus remain distinct. Keep the Fragments single-selection and arrow-key behavior. Do not use it for independent on/off choices or as a substitute for ordinary links.

## Workspace layout

### Launch splash

`SplashScreen` fills the window at renderer startup while the initial snapshot loads. Three vector arches echo the app icon in lemon/lime/lemon, snaking along straight paths with crisp 90-degree turns from the left, right and bottom edges, holding as a logo and unwinding along right-angle exit paths over 2.6 seconds; the settled logo retains its curved arches. The canvas, ambient lemon-soft/lime-soft glow, and ink wordmark use semantic tokens. The mark scales with the window; native macOS window controls remain available.

Any key or a click dismisses immediately; no visible skip hint is shown. The full surface is an accessible skip button, focused on launch without a perimeter focus ring because any key dismisses it; the dismissal key is consumed and workspace shortcuts stay disabled during the intro. Reduced-motion users see a static mark for 180 ms. The splash plays once per renderer mount, never on navigation or ordinary window reopening. It is time bounded independently of data loading; slow startup returns to the existing loading state after dismissal. It is not an onboarding or progress screen.

The app is a left sidebar plus one working area; there is no top navigation. Views live in `src/ui/views/` and share `src/ui/workspace.scss`. Two-column views (task list + detail, thread list + thread, run list + log) put the list on the left and keep the list's width fixed so the working column absorbs resizing.

### Sidebar

The workspace navigation. It has no in-app product lockup; the top inset leaves a clean drag region below the macOS window controls. Sections, in order: **Tasks** (Needs you with a lemon count badge, Today, Upcoming, Delegated, Completed), **Groups** (with a + to create one), **Agents** (each agent's private group; the second line shows "Working · <thread>" while it runs), **Routines** (next run, Paused, Running, or Failed). There is no sidebar footer; Settings opens from the Aegir application menu, the menu-bar tray, or `Cmd+,`. The active item uses the pale `--ds-color-nav-selected` fill without a border, semibold text, and `aria-current="page"`. Keyboard focus is a separate thin inset ring using `--ds-color-focus`, contained within the item so adjacent navigation rows never overlap. Counts and routine states are text, never colour alone. Section add buttons and numeric counts share a centered 24 px trailing column and the same right inset, including attention badges and custom lists. Counts use tabular numerals; longer routine status labels retain their natural width. `J/K` moves focus among sidebar items; `Enter` opens one and `L` enters its content.

### Task list

A dense, keyboard-first list modelled on Godspeed. Rows are one line, 34 px tall: status glyph, title, optional source or attached-link icon, agent avatars plus a one-word state (working, review, blocked), and due date (overdue in amber). Open rows are grouped by label; in Needs you they are grouped by status and show their label inline. Completed tasks have their own list, newest completion first, with Space or the detail action to reopen.

- **Glyphs** (`TaskGlyph`): an empty circle for your open task, a spinning partial lime ring while the team works, a lemon "!" for review or blocked, a spark for a suggestion, and a filled check for done. Each has an accessible label.
- **Cursor and panes**: the selected row uses the lime-soft selection style and scrolls into view. `J/K` or Up/Down moves it. `H` or Left moves into the sidebar; the highlighted task always appears in the detail pane. Right/L no longer enters task details. N focuses notes; A starts handoff or focuses chat for a handed-off task. Escape returns focus to the highlighted row while keeping the detail pane visible, including from chat, title, and notes; a mention picker or document consumes the first Escape while open. The same pane motions work in group and routine lists. Selection is retained per task list.
- **Shortcuts** appear in the hold-§ overlay and must stay in sync with the handler: `Space` completes or reopens, `Enter` edits the selected title, `N` edits notes, `A` hands off or focuses chat, `Shift+A` opens the exact conversation in its channel, `Cmd+L` sets a label (`B` remains an alias), `Shift+B` clears it, `D` sets a due date, `Shift+D` clears it, `Cmd+N` creates a task, `Cmd+O` opens the task output folder or, when absent, its attachment, `Cmd+V` attaches a copied URL, app deep link, or local file path, `Cmd+Z` undoes the last local task action, `Y` accepts, and Backspace/Delete dismisses a suggestion or deletes a non-running task with undo. `G` then `T/U/W/N/C` jumps to a task list. Shortcuts are ignored while typing in a field; text editors retain native undo.
- **Quick add** is one line above open task lists without a persistent keyboard hint; it parses `#label` and date words. The completed list has no quick add field. Successful creation clears the field and focuses the selected task row once the updated list arrives; if the new task belongs to another list, focus returns to the current row or empty list pane. Failed creation retains the draft.

### Task popovers

Anchored under the row. The hand-off popover has a title, one instruction field and a footer stating that Atlas routes the work and that results are saved as files; `↵` submits, `⇧↵` adds a line, `Esc` cancels. The label and due popovers are a single field that commits on `↵` or blur; empty input clears the value, while an invalid date stays open with an inline error. Do not add agent pickers or autonomy settings here: hand-off is intentionally one instruction.

### Task detail

The always-visible right-hand pane (440 px by default, 380 px in compact windows) follows the highlighted task and keeps title, notes, status, source links, and conversation together. Label and due-date fields, completion controls, delete/close icons, and the Output button are omitted. Edit labels from the highlighted task with Cmd+L and dates with D; the task list displays both. Cmd+O opens the highlighted task’s output folder when available, otherwise its single attachment. If neither exists it produces a notice.

Drag the task/detail boundary to resize the pane. Its 8 px hit target keeps the one-pixel resting border and highlights with lime-strong on hover, keyboard focus, and while dragging. The focusable vertical separator announces its width; Left/Right adjust by 10 px (Shift by 50), Home/End move the boundary to its limits, and Enter or double-click resets the default. Width is remembered locally across task changes and app restarts. Reserve at least 280 px for the list and normally 340 px for details; smaller windows temporarily clamp the width without overwriting the preference. Hide this divider while a document is open, when the document workspace owns the available space.

Enter on a highlighted row edits its title; Enter saves and returns focus to the list. N focuses notes. Escape cancels an in-progress title/notes edit and returns focus to the task list; from chat it returns to the list after dismissing any open mention picker. The sidebar remains visible. N focuses notes; A starts handoff or focuses the existing chat. Right/L on a task no longer moves focus. Unhanded tasks omit the “Your task” header. Space completes/reopens from the list. Backspace/Delete removes a non-running task (or dismisses a suggestion); Cmd+Z restores deleted task data and its conversation. The channel label is a ghost Button that opens the linked conversation directly; long labels truncate with a tooltip, and Shift+A provides the same action from the task row. The destination selects the Tasks filter so closed task threads remain visible, and focuses the selected thread row. Running tasks retain the Stop action. Hand off remains available for tasks without a conversation. Attached links retain their individual remove actions and source provenance. Each task has at most one attachment; pasting replaces it, and undo restores the previous attachment. A multiline paste keeps the last non-empty line. Existing tasks with multiple attachments retain their newest one. Paste an absolute path, a quoted path, a ~/ path, or a file:// URL onto a highlighted task with Cmd+V to attach a local file. Paths with spaces are encoded correctly and display the filename. Clicking opens the file in its default macOS application; missing files report an error. Local opening is restricted to saved attachments, while ordinary chat links retain the external-link policy.


### Thread list and thread

New group and private chats initially use the opening message as a fallback title. The first responding agent is instructed to set a short topic-based title through `threads__set_title` before answering. The title updates in the thread list and conversation header without adding a message. If no valid suggestion arrives, the fallback remains. Follow-up turns do not rename the chat, and task threads retain their task titles. Late suggestions cannot overwrite a changed title or rename a closed chat.

A group view lists its threads (title, status chip for task threads, last message snippet, participating agents, count and time) with Active / Tasks / Closed filters and a "Start a thread" field. Cmd+N focuses “Start a thread” in the current group or private chat, preserving any existing draft; Enter submits it. Outside chats, Cmd+N still opens task quick-add. When a document hides the thread list, close it with Escape first so unsaved edits can be saved. Private groups show the agent's avatar and "Private · just you and <agent>".

Messages render Markdown headings, emphasis, lists, code, quotes, and GFM tables using `ChatMarkdown`; raw HTML is not executed. External links use the app’s link-opening API. Code blocks and tables scroll within the message, including in the compact task detail pane. Messages are Slack-style, not bubbles: avatar, name, role chip, time, then text. Failures and streaming are shown in words and a typing indicator. System events are a single muted line with an arrow. Routine changes render as a card listing the before → after values, with Apply / Discard while pending and the outcome afterwards.

Each user and agent message has a visible icon-only **Copy message** ghost button below its text (`CopyMessageButton`), aligned to the start of the message body in full conversations, compact task chats and document split panes. A 14 px icon sits in a compact 24 px target with 4 px spacing above it. It copies the exact message text as Markdown, preserving links, code and whitespace without adding author or timestamp. Nonempty streaming and failed replies can be copied; an empty reply disables the action. The button supports Tab and Enter/Space, disables while pending, confirms success briefly with a check icon and live announcement, and offers a retry through its accessible name and tooltip on failure. Tooltips describe pending and copied states without adding visible labels. It uses muted ink and the shared Button's hover and focus tokens, stays visible without hover, and introduces no animation.

The Copy chat button copies the entire saved conversation as Markdown, including messages outside the currently loaded page, speaker names, local dates/times, source links, system events, and proposal status. In-progress replies are copied as a snapshot and marked incomplete. It sits with Files in normal headers and at the right of the Conversation pane header while editing a document. Compact task headers use one top toolbar: a content-width channel link on the left, then Files and Copy chat on the right. All three use the same small ghost Button; long channel names truncate with the full name available in the tooltip. Notes fill the pane below. The redundant Ready for review badge is omitted from task details. Group headers keep Files and Copy chat inline and wrap them below the title when space is tight. The button uses the shared ghost Button, shows Copying / Copied / Retry copy feedback, announces success or failure without moving focus, and is disabled for empty or initially loading conversations. It never copies an unsent composer draft or document contents.

While the thread is busy, a persistent “Working…” status sits above the composer, outside the scrolling message list. It remains visible after partial replies and during silent reasoning or tool use, in both full conversations and compact task details. It disappears when the run finishes, fails, or stops. The status uses muted text and lime-strong dots, announces itself with `role="status"`, and never moves keyboard focus. Decorative dots stop animating with reduced motion; the text remains visible.

Skill revisions render as `SkillChangeCard` in group/private conversations and compact task chats. The card names the skill, shows the reason and current saved status, and offers Review changes / Discard while pending. Review expands a shared `PackageDiff` with labeled Before and Proposed contents for every changed file; Apply revision appears only after opening the comparison. Stale proposals explain how to merge in Manage skills. Applied and discarded cards remain in history with reviewable contents. Status refreshes after changes in Settings, and loading, missing-proposal, and retryable failure states are explicit. Buttons disable during actions, retain keyboard focus indicators, and use the existing Fragments primitives. Surface, line, ink and muted tokens define the card. Comparisons stack vertically within the narrow chat column; long paths wrap and file contents scroll. No animation is introduced.

### Composer

A two-line textarea that grows with content, with a lime send button that is muted while empty. `↵` sends and `⇧↵` adds a line. Typing `@` opens the mention picker, with routines listed above agents; arrows move, `↵`/`Tab` insert, and `Esc` closes. In group/private chats, Escape leaves the message editor and focuses the selected thread in the middle list without clearing the draft; H/Left can then return to the sidebar. An open mention picker consumes the first Escape. Task chats retain Escape-to-task-list behavior, and an open document retains save-and-close priority. Stop appears while an agent in the thread is running.

Typing `/` at a word boundary opens the skill picker in full and compact composers. It searches names and descriptions, shows shared or agent-owned scope, and filters disabled, archived, broken, or incompatible skills against all current recipients (the lead by default, explicit @mentions otherwise). Enter/Tab selects; Escape dismisses even an empty picker without leaving the composer. Loading, retryable errors, and no matches are explicit. Choosing a skill adds a removable chip and preserves surrounding draft text. Sending loads its stable ID; failed sends restore chips with the draft, and changing recipients blocks sending incompatible selections. Runtime tool requirements remain authoritative. The picker uses surface, line, lime-soft, ink, and muted tokens, stays within the compact pane, scrolls long results, and announces active options without moving textarea focus.

### Document workspace

`ThreadView` opens local Markdown links and a Files picker in both group conversations and task details. Opening a document collapses the sidebar into an accessible icon rail, hides the thread/task list, and places the conversation beside `DocumentEditor`. While editing, a 56 px window header spans the entire window above the navigation rail and both panes. Its first 104 px are reserved for native macOS controls (positioned at x=16, y=20); the remaining space shows the group and conversation title as a quiet breadcrumb. The title truncates with a full-text tooltip; long group names also truncate. This is the draggable window surface, with interactive controls excluded from dragging. The rail begins below it with compact top spacing, so no sidebar boundary passes through the traffic lights. Matching 48 px pane headers label Conversation and the document, keeping filename and file actions at the document level. A one-pixel divider separates panes within the existing wider resize target, strengthening on hover or keyboard focus. The window bar uses glass, line, ink and muted tokens without animation. At compact widths, the existing Conversation / Document buttons stay in the window bar; task fields and normal header spacing return when the document closes. Files sits beside the document filename while editing and beside the conversation header otherwise, with no separate toolbar row. Closing restores the existing navigation, conversation, and composer without remounting them. The separator supports pointer dragging and arrow-key resizing from 25–55% conversation width. At widths up to 1000 px, Conversation / Document controls switch surfaces.

The document is always formatted and directly editable. While the caret is in a heading, muted monospace `#` markers in the left margin indicate its level without becoming editable content or changing Markdown. Backspace at the start of a heading removes one `#` level; removing the last level turns it into a paragraph. This preserves the preceding paragraph, text formatting and caret position, and supports undo. Backspace within text and deletion of a selected range keep their ordinary behavior. The prose gutter reserves space for all six levels. There is no source toggle, draft/byline header, or suggestions card. The header contains the filename, save state, and close action. Surface/canvas, ink/muted, and line tokens define the editor; lime-soft highlights text selection and referenced passages. Editing uses native undo, Markdown input shortcuts, and Cmd+B / Cmd+I. Headings, lists, code, quotes, tables, images, and checklists serialize back to Markdown; formatting syntax can normalize on edit. HTML, frontmatter, and footnotes are currently read only to avoid dropping unsupported content.

Type `/` on an otherwise empty paragraph to open the formatting insertion menu. Search narrows tables, links, bullet/numbered lists, checklists, quotes, code blocks, and dividers. Arrow keys choose; Enter/Tab inserts; Escape dismisses before the document closes. The menu stays near the caret inside the pane, scrolls within its height limit, and uses surface, line, lime-soft selection, and muted descriptions. Code blocks and read-only documents do not offer commands. Table insertion starts with three columns and three rows, including a header, and retains the existing table controls. Link insertion opens a labeled Text/Destination form; Cmd+K uses the current selection as link text. Cancel preserves document content; invalid destinations or a changed document retain the form with an error. These actions use normal editor undo and autosave, with no animation.

The Files popover closes on outside pointer interaction or focus moving outside it. Escape dismisses the popover and returns focus to Files before the workspace handles document closing. Each row has separate keyboard-accessible targets: its filename opens the editor, and a Show in Finder icon reveals the existing file’s location without opening the editor. Finder actions use the same workspace path and symlink restrictions as document access; missing files report an error. Long paths wrap while the icon remains reachable.

The document header’s Copy button copies the full current Markdown source, including unsaved or recovered edits and content in read-only documents. It does not change the selection or save the file. The existing status area briefly announces success or clipboard failure.

The header's independent **Focus mode** and **Typewriter mode** icon buttons expose accessible names, tooltips and pressed states, using lime-soft, lime-ink and line tokens when active. Focus fills the app window, hiding navigation, the conversation and the resize divider while retaining the editor instance, draft, selection and undo history. Its 56 px draggable document header reserves 104 px for native window controls and retains Files, Copy, save status and Close. Escape dismisses open editor popovers first, then exits focus mode; a subsequent Escape saves and closes the document. F6 stays in the editor while focus mode is active. Leaving focus restores the existing split layout and conversation draft in both task and group workspaces.

Typewriter mode centers the visual caret line after typing or moving a collapsed selection, including wrapped paragraphs. Half a viewport of breathing room at each end permits centering the first and last lines. It adapts to pane resizing and content reflow. Manual scrolling remains free until editing resumes; selecting a passage does not move the viewport. Canvas gradients fade the top and bottom 72 px (at most 15% of the writing viewport), leaving toolbars, alerts, popovers and pointer interaction unaffected. Centering is immediate, with no animated scrolling, including reduced-motion mode. Typewriter is unavailable for read-only Markdown. Both modes are local to the open document and do not change its saved content.

Typing two consecutive hyphens (`--`) in prose replaces them with an em dash (`—`). Immediate Backspace reverses the substitution so literal double hyphens remain available. Inline code, code blocks and editable link source keep literal hyphens; opening or pasting existing Markdown does not run this substitution. The resulting text participates in ordinary undo, autosave and Copy. Use the `/` formatting menu to insert a divider.

#### Floating outline and scratchpad

`DocumentCompanion` is a floating glass card at the left of the document's writing viewport, available in both split and focus mode. The **Outline and notes** header button shows or hides it; its expanded state and panel name are accessible. The card stays in place while prose scrolls, independently scrolls long contents, and sits above typewriter fades. At editor widths of 760 px or more, a reserved left gutter keeps it clear of the text. Smaller panes initially tuck it away and offer it as a dismissible overlay; resizing below that width also tucks it away. Choosing a heading in an overlay closes the card and focuses the destination. A close button returns focus to the header toggle. The card is at most 420 px high (340 px in narrow panes), bounded by available viewport height.

A shared `ToggleGroup` at the top switches **Contents / Scratchpad**, with a lime-soft selection pill that slides for 160 ms; reduced-motion mode removes that transition. Arrow keys move between modes without invoking workspace navigation. Contents lists live H1–H6 headings with their level, indentation and wrapped labels, including unsaved changes and external reloads. Duplicate titles navigate by document position. The current section has a visible selection marker and `aria-current`; clicking a heading moves the caret and scrolls it into view, centering it when typewriter mode is enabled. Empty documents explain that headings build the outline. Read-only documents still support navigation.

Scratchpad is an independent rich-text editor for rough outlines and general notes. Its compact toolbar provides Bold, Italic, Bullet list, Decrease indent and Increase indent; active formatting uses pressed states and lime-soft/lime-ink tokens. Cmd/Ctrl+B and Cmd/Ctrl+I style text. Tab/Shift+Tab nest and unnest list items; Cmd/Ctrl+]/[ or the toolbar indent and outdent paragraphs (up to six levels) and lists. Outside lists, Tab retains ordinary focus navigation. The writing area scrolls independently beneath the toolbar and uses the editor font; an empty pad shows a quiet placeholder. Formatting is stored in versioned local editor data, and existing plain-text notes load literally with their line breaks preserved. Notes save locally on each edit, scoped to the open document and conversation, separately from Markdown, Copy, autosave and passage references. Switching modes or hiding the card retains notes and the scratchpad’s independent undo history; reopening restores saved notes. Read-only Markdown still permits scratchpad notes. A quiet status indicates local persistence; load failures disable editing until Retry succeeds, and save failures preserve the in-memory draft with an explicit retry action. Escape from within the panel hides it before document/focus-mode navigation. Surface/glass, line, ink/muted, lime-soft/lime-ink, focus and danger tokens define its appearance and states.

Document links open on click. Web links use the app’s external-link handler; local Markdown links resolve relative to the current document and use the existing save-before-switching flow. Moving the text caret into a link reveals its Markdown source inline, including the label and destination. Moving the selection outside restores formatted rendering. The source uses monospace text, ink, and surface tokens and wraps long destinations within the prose width. Autosave and Copy retain Markdown syntax while a link is being edited; read-only documents keep their links clickable without exposing an editable source state. Failed link opening appears in the document’s existing error alert.

#### Passage comments

Selecting editable prose reveals a small **Comment** action beside the passage; Cmd/Ctrl+Shift+M opens the same form. `DocumentComments` provides a labeled comment field, Save comment and Cancel. Cmd/Ctrl+Enter saves; Escape dismisses the comment UI before workspace navigation. Whitespace-only comments cannot be saved. Code, link-source text, and selections overlapping an existing comment do not offer a new comment. Existing comments have Edit and Delete actions; deletion supports ordinary document undo.

Commented text has a quiet lemon highlight and dotted underline. Hovering it or moving the caret into it shows the comment without moving focus. The popover remains reachable when moving the pointer into its actions. It wraps long comments, scrolls within the viewport, and uses surface, ink, muted, line, focus and lemon-soft tokens without animation. Read-only documents allow viewing comments but not changing them. The original selection-to-chat behavior remains available.

Annotations are document marks that move with edits and disappear if their entire passage is deleted. Each comment has a stable ID and text, stored in validated, encoded `aegir:comment` HTML comment delimiters around its Markdown passage. A comment spanning blocks uses the same ID on each segment; editing/deleting it affects every segment. This format participates in autosave, local recovery, Copy, undo and disk-conflict handling; malformed annotations retain the existing read-only protection. The comment form refuses to apply to a document that changed while it was open, retaining the draft for review.

Selecting text automatically attaches a removable, labeled passage to the composer without moving focus. The next sent message includes the file path and quoted passage. Clearing a selection in the editor or sending the message clears the reference. Unsaved document changes are flushed before sending so the team receives current file contents.

Edits autosave after a short pause, with explicit Saving / Saved / Not saved states. The main process restricts reads and writes to the agent's working folder, rejects symlinks and oversized files, checks a content revision before replacing the file, and writes through a temporary file. Local recovery drafts survive navigation and restarts. External file edits refresh a clean editor; when local changes exist, the editor preserves them and presents Retry save / Reload file. Reload requires an explicit discard action. This is file-based collaboration, not simultaneous live cursor editing.

Esc saves and closes the document, except while a mention picker consumes Escape. A failed save keeps the document open. F6 switches focus between the document and conversation; Cmd+S saves. H/Left from the conversation closes the document, and L/Right enters its pane outside text fields. Hold § to discover the document shortcuts. Icon rail items retain names and tooltips, and the resize separator exposes its current value.

The document pane and editable prose have no focus outline. Buttons, links, and the resize separator retain their visible keyboard focus indicators.

#### Editable tables

`DocumentTable` supplies the same table controls in task and group document panes. Hovering a table, placing the caret inside it, or focusing a control reveals quiet “+” rails along its bottom and right edges. Click or activate with Enter/Space to append one row/column; drag outward to preview and append several (up to 20 per gesture). Release commits one undoable edit. Drag back to the starting edge to add nothing; Escape, pointer cancellation, or losing window focus cancels without changing content. These handles add cells; they do not resize column widths or remove existing content. Wide tables scroll inside the document pane, keeping both rails reachable.

The First row control selects that row, exposing the Header row toggle. Placing the caret in the first row also exposes the toggle. Its pressed state reflects header styling; toggling preserves all cell text and alignment. Header cells use lime-soft and semibold ink, while selected cells receive a separate translucent lime overlay. Buttons use surface, muted, line and focus tokens; keyboard focus remains visible. Controls are hidden in read-only documents and remain discoverable on touch devices. There are no animations.

Grip buttons above each column and beside each row reorder table content. Drag a grip to an insertion line; a text hint announces the destination. Click selects the whole row or column; Alt+Up/Down on a row grip and Alt+Left/Right on a column grip move it using the keyboard. Each move is one undo step and participates in autosave. Cell content, formatting and alignment move together, while the table's header setting stays attached to the first row. ## States and accessibility
