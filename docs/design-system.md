# Aegir design system

The Lime Glass direction is being introduced one section at a time. The [Paper Tasks sketch](https://app.paper.design/file/01M35BFSHJZGNPY821ZEJG3MQ2/p-1-0/BR-0) defines the compact layout. The third image in `design/concepts/03-lime-glass.png` defines the color and atmosphere. The workspace (sidebar, Tasks, threads, Routines) is fully on Lime Glass; Memory and Settings still use some legacy styles from `light.scss`. The layouts follow the sketch canvas agreed in September 2026.

## Foundations

The source of truth for new semantic values is `src/ui/design-system/tokens.scss`. Use tokens in component styles rather than repeating hex values. Existing blue styles in `light.scss` remain until their sections are migrated.

| Role | Token | Value | Use |
| --- | --- | --- | --- |
| Canvas | `--ds-color-canvas` | `#fcfdf9` | Quiet app ground |
| Surface | `--ds-color-surface` | `#ffffff` | Opaque controls |
| Glass | `--ds-color-glass` | `#ffffffd9` | Panels over ambient color |
| Ink | `--ds-color-ink` | `#1f2b1d` | Primary text and icons |
| Muted | `--ds-color-muted` | `#596753` | Secondary text and timestamps |
| Line | `--ds-color-line` | `#dfe7d8` | Borders and dividers |
| Lime | `--ds-color-lime` | `#a9e929` | Primary action and active state |
| Lime soft | `--ds-color-lime-soft` | `#edf8d2` | User messages and subtle selection |
| Lime ink | `--ds-color-lime-ink` | `#42622c` | Text on pale lime surfaces |
| Lemon | `--ds-color-lemon` | `#ffe95e` | Ambient light and sparing emphasis |
| Link | `--ds-color-link` | `#366d36` | Source links inside chat bubbles |

Typography is selected in Settings → Fonts. `--ds-font-system` covers the app's headings, navigation, controls, conversations, and splash-screen name; `--ds-font-editor` covers Markdown document content, including its headings. Both default to Inter. The body and heading tokens alias the system font except inside document prose. Editor toolbars keep the system font, while code and logs retain monospace. Fonts are bundled locally through Fontsource and work offline. Text sizes are controlled independently: app text scales from 90–130% (100% by default), Markdown body text from 12–24 px (14 px by default), and scratchpad text from 11–20 px (13 px by default). `--ds-system-text-scale`, `--ds-editor-text-scale` and `--ds-scratchpad-text-scale` feed the scoped `--ds-text-scale` token. Font-size declarations scale their established hierarchy; layout dimensions and icons stay stable. Document headings and table cells follow the Markdown size; table controls follow app size. Scratchpad controls follow app size while its prose has its own scale. Code retains its monospace family and follows its surrounding text scale. The small labels in the compact pane must still be readable at the app's 900 px minimum width.

Use `--ds-space-1` through `--ds-space-6` for recurring 4, 8, 12, 16, 20 and 24 px spacing. Task preview sections use 20 px insets and 12 px gaps; compact control groups use 4–8 px gaps.

Ambient color belongs behind the content. Only translucent surfaces receive backdrop blur. Never blur text, icons, or the message content itself. Use a 1 px boundary to keep each glass panel legible when the background glow changes. Motion must respect reduced-motion preferences.

## Shared primitives

`src/ui/design-system/primitives.tsx` adapts the Fragments components already in use. Import these Aegir exports in product views instead of importing the same components directly from `@usefragments/ui`. Their Fragments foundations retain semantics, keyboard behavior, and core sizing; `primitives.scss` applies our tokens and visual states. `ThemeProvider` remains a library integration, not a product component. The chat `Prompt` is adapted through `ChatComposer` below.

### `Button`

Use for actions, not navigation labels or passive status. Its anatomy is a label with an optional leading or trailing icon; icon-only buttons require an accessible name. Default solid/accent is the lime primary action. Use `outline` for secondary actions, `ghost` in dense rows and toolbars, and `link` for tertiary actions. Keep one dominant solid action in an action group. The wrapper retains Fragments' `size`, `icon`, `fullWidth`, disabled, and keyboard behavior. Lime, surface, ink, border, and disabled tokens define its states; hover and focus must remain visible.

### `Badge`

Use for short, non-interactive counts, categories, or status. The label is required; an optional dot reinforces status but never replaces text. `neutral` is ordinary metadata, `info`/`accent` are lime emphasis, `success` and `danger` are outcome states, and `warning` is lemon. `soft` is the default pill; use `outline` only when a filled badge would compete with nearby content. Preserve a readable label at small size and request status announcement only when a live change needs it.

### `Card`

Use to group related content with a clear boundary. `solid` is an opaque elevated surface, `outline` is a milky glass panel, and `soft` is a quiet lime-tinted grouping. The border and radius come from tokens; only glass receives backdrop blur. Use `padding="none"` when the contents own their insets or include an internal divider. Keep headings and interactive elements semantic inside the card; a card is not automatically clickable.

### `ToggleGroup`

Use for a small set of mutually exclusive views or filters. The current workspace switcher is the first use. The group contains labeled items, with the selected item on a soft lime surface; hover and keyboard focus remain distinct. Keep the Fragments single-selection and arrow-key behavior. Do not use it for independent on/off choices or as a substitute for ordinary links.

## Workspace layout

### Launch splash

`SplashScreen` fills the window at renderer startup while the initial snapshot loads. Three vector arches echo the app icon in lemon/lime/lemon, snaking along straight paths with crisp 90-degree turns from the left, right and bottom edges, holding as a logo and unwinding along right-angle exit paths over 2.6 seconds; the settled logo retains its curved arches. The canvas, ambient lemon-soft/lime-soft glow, and ink wordmark use semantic tokens. The mark scales with the window; native macOS window controls remain available.

Any key or a click dismisses immediately; no visible skip hint is shown. The full surface is an accessible skip button, focused on launch without a perimeter focus ring because any key dismisses it; the dismissal key is consumed and workspace shortcuts stay disabled during the intro. Reduced-motion users see a static mark for 180 ms. The splash plays once per renderer mount, never on navigation or ordinary window reopening. It is time bounded independently of data loading; slow startup returns to the existing loading state after dismissal. It is not an onboarding or progress screen.

The app is a left sidebar plus one working area; there is no top navigation. Views live in `src/ui/views/` and share `src/ui/workspace.scss`. Two-column views (task list + detail, thread list + thread, run list + log) put the list on the left and keep the list's width fixed so the working column absorbs resizing.

### Sidebar

The workspace navigation. It has no in-app product lockup; the top inset leaves a clean drag region below the macOS window controls. Sections, in order: **Tasks** (Needs you with a lemon count badge, Today, Upcoming, Delegated, Completed), **Chats** (All threads, plus a + to focus the new-thread field; count shows active chat threads), **Routines** (next run, Paused, Running, or Failed). A UI comments launcher sits at the bottom left; Settings opens from the Aegir application menu, the menu-bar tray, or `Cmd+,`. The active item uses the pale `--ds-color-nav-selected` fill without a border, semibold text, and `aria-current="page"`. Keyboard focus is a separate thin inset ring using `--ds-color-focus`, contained within the item so adjacent navigation rows never overlap. Counts and routine states are text, never colour alone. Section add buttons and numeric counts share a centered 24 px trailing column and the same right inset, including attention badges and custom lists. Counts use tabular numerals; longer routine status labels retain their natural width. `J/K` moves focus among sidebar items; `Enter` opens one and `L` enters its content.

### Task list

A dense, keyboard-first list modelled on Godspeed. Rows are one line, 34 px tall: status glyph, title, agent avatars plus a one-word state (working, review, blocked), and due date (overdue in amber). Open rows are grouped by label; in Needs you they are grouped by status and show their label inline. Completed tasks have their own list, newest completion first, with Space or the detail action to reopen.

- **Glyphs** (`TaskGlyph`): an empty circle for your open task, a spinning partial lime ring while the team works, a lemon "!" for review or blocked, a spark for a suggestion, and a filled check for done. Each has an accessible label. In task rows, the glyph sits in a 24 px ghost button that completes the task, or reopens a completed task, with a task-specific accessible name. Click, Enter, and Space activate it; keyboard activation does not trigger row shortcuts. The button keeps the 16 px glyph and existing row alignment, uses lime hover and focus tokens, and disables while saving to prevent duplicate actions. Failures use the workspace error notice and leave the task available to retry.
- **Cursor and panes**: the selected row uses the lime-soft selection style and scrolls into view. `J/K` or Up/Down moves it. `H` or Left moves into the sidebar; the highlighted task always appears in the detail pane. Right/L no longer enters task details. N focuses notes; A starts handoff or focuses chat for a handed-off task. Escape returns focus to the highlighted row while keeping the detail pane visible, including from chat, title, and notes; a mention picker or document consumes the first Escape while open. The same pane motions work in thread and routine lists. Selection is retained per task list.
- **Shortcuts** appear in the hold-§ overlay and must stay in sync with the handler: `Space` completes or reopens, `Enter` edits the selected title, `N` edits notes, `A` hands off or focuses chat, `Shift+A` opens the exact conversation in Chats, `Cmd+L` sets a label (`B` remains an alias), `Shift+B` clears it, `D` sets a due date, `Shift+D` clears it, `Cmd+N` creates a task, `Cmd+O` opens the task output folder or, when absent, its attachment, `Cmd+V` attaches a copied URL, app deep link, or local file path, `Cmd+Z` undoes the last local task action, `Y` accepts, and Backspace/Delete dismisses a suggestion or deletes a non-running task with undo. `G` then `T/U/W/N/C` jumps to a task list. Shortcuts are ignored while typing in a field; text editors retain native undo.
- **Quick add** is one line above open task lists without a persistent keyboard hint; it parses `#label` and date words. The completed list has no quick add field. Successful creation clears the field and focuses the selected task row once the updated list arrives; if the new task belongs to another list, focus returns to the current row or empty list pane. Failed creation retains the draft. Keep filters and quick add separated by spacing, without a divider. The field leads with a plus and text; a More disclosure at the trailing edge offers Organize with AI, explaining the proposed title, notes, labels and date before the user reviews the result. The action disables for empty input and while preparing; failures preserve the note.

### Task repetition

`TaskRepeat` is a small ghost action at the top of task details, showing **Repeat** or the saved cadence. It opens a modal matching the Move picker: title, task name, schedule choices, and a brief completion explanation. Choices are Does not repeat, Daily, Weekdays, Weekly and Monthly. The current choice uses lime-soft, a check and a Current label. Arrow keys or J/K move through choices; Enter/Space saves. Escape/outside click cancels, and focus returns to the trigger. Saving disables choices and dismissal and announces progress. Failure leaves the modal open with the persisted choice and a retryable alert. Completed/dismissed history opens a read-only picker pointing to the next occurrence. Use surface, ink, line, muted, focus and lime tokens, with the same compact target and spacing in every task preview.

An accessible repeat icon marks recurring task rows. Completion creates the next task and skips missed dates. Quick add still accepts `every day`, `every weekday`, `every week`, and `every month`, alongside dates and labels.

### Task popovers

Anchored under the row. The hand-off popover has a title, one instruction field and a footer stating that the main assistant handles the work and that results are saved as files; `↵` submits, `⇧↵` adds a line, `Esc` cancels. The due popover commits on `↵` or blur; empty clears it, while an invalid date stays open with an inline error. B opens the Task labels dialog described below. Do not add agent pickers or autonomy settings here: hand-off is intentionally one instruction.

### Task detail

The always-visible right-hand pane (440 px by default, 380 px in compact windows) follows the highlighted task and keeps title, notes, status, source links, and conversation together. Preserve that preview structure, with consistent 20 px section insets and 12 px vertical gaps. Repeat is available under Task options below the title. Below the notes, generated Markdown files appear as individual rows: show up to three most recently updated files, then **View all · N documents** when more exist. The header region scrolls when long so the conversation and composer remain usable. Task options holds label editing and the Today action; the dedicated due-date editor remains available with D. Completion controls, delete/close icons and the Output button are omitted. Edit labels from the highlighted task with Cmd+L and dates with D; the task list displays both. Cmd+O opens the highlighted task’s output folder when available, otherwise its single attachment. If neither exists it produces a notice.

Drag the task/detail boundary to resize the pane. Its 8 px hit target keeps the one-pixel resting border and highlights with lime-strong on hover, keyboard focus, and while dragging. The focusable vertical separator announces its width; Left/Right adjust by 10 px (Shift by 50), Home/End move the boundary to its limits, and Enter or double-click resets the default. Width is remembered locally across task changes and app restarts. Either pane can shrink to a 24 px sliver, keeping the divider reachable. Below 280 px for the list or 340 px for details, clip the content at its readable minimum width instead of squeezing it; focusing a control inside a clipped pane restores enough room to use it. Smaller windows temporarily clamp the visible width without overwriting the preference. Hide this divider while a document is open, when the document workspace owns the available space.

Enter on a highlighted row edits its title; Enter saves and returns focus to the list. N focuses notes. Escape cancels an in-progress title/notes edit and returns focus to the task list; from chat it returns to the list after dismissing any open mention picker. The sidebar remains visible. N focuses notes; A starts handoff or focuses the existing chat. Right/L on a task no longer moves focus. Unhanded tasks omit the “Your task” header. Space completes/reopens from the list. Backspace/Delete removes a non-running task (or dismisses a suggestion); Cmd+Z restores deleted task data and its conversation. The Conversation ghost Button opens the linked thread directly; Shift+A provides the same action from the task row. The destination selects the Tasks filter so closed task threads remain visible, and focuses the selected thread row. Running tasks retain the Stop action. Hand off remains available for tasks without a conversation. Attached links retain their individual remove actions and source provenance. Each task has at most one attachment; pasting replaces it, and undo restores the previous attachment. A multiline paste keeps the last non-empty line. Existing tasks with multiple attachments retain their newest one. Paste an absolute path, a quoted path, a ~/ path, or a file:// URL onto a highlighted task with Cmd+V to attach a local file. Paths with spaces are encoded correctly and display the filename. Clicking opens the file in its default macOS application; missing files report an error. Local opening is restricted to saved attachments, while ordinary chat links retain the external-link policy.


### Chats and threads

New threads initially use the opening message as a fallback title. The first responding agent is instructed to set a short topic-based title through `threads__set_title` before answering. The title updates in the thread list and conversation header without adding a message. If no valid suggestion arrives, the fallback remains. Follow-up turns do not rename the chat, and task threads retain their task titles. Late suggestions cannot overwrite a changed title or rename a closed chat.

`ThreadsView` shows one list across former channels and the main assistant’s private conversations. The header is Chats with “With <assistant>” beneath it; no channel labels, agent lists or private-chat sections remain. Active shows open chat threads, Tasks shows task conversations, and Closed shows closed threads. Thread rows contain title, optional task state, snippet, message count and time; working state has an accessible text label. A “Start a thread” field creates a conversation with the main assistant; it disables and announces Starting while saving, retains text on failure, and clears on success. Cmd+N focuses it while preserving an existing draft. New thread is also available from the sidebar and palette. If a document is open, close it with Escape first so unsaved edits can be saved. Selecting a task conversation or palette result opens the matching tab and exact thread. Closing a thread switches to Closed. Empty tabs explain what appears there. J/K, arrows and pane navigation retain their existing behavior. Layout uses the established list/detail panes at wide and compact widths.

Messages render Markdown headings, emphasis, lists, code, quotes, and GFM tables using `ChatMarkdown`; raw HTML is not executed. External links use the app’s link-opening API. Code blocks and tables scroll within the message, including in the compact task detail pane. Messages are Slack-style, not bubbles: avatar, name, role chip, time, then text. Failures and streaming are shown in words and a typing indicator. System events are a single muted line with an arrow. Routine changes render as a card listing the before → after values, with Apply / Discard while pending and the outcome afterwards.

Each user and agent message has a visible icon-only **Copy message** ghost button below its text (`CopyMessageButton`), aligned to the start of the message body in full conversations, compact task chats and document split panes. A 14 px icon sits in a compact 24 px target with 4 px spacing above it. It copies the exact message text as Markdown, preserving links, code and whitespace without adding author or timestamp. Nonempty streaming and failed replies can be copied; an empty reply disables the action. The button supports Tab and Enter/Space, disables while pending, confirms success briefly with a check icon and live announcement, and offers a retry through its accessible name and tooltip on failure. Tooltips describe pending and copied states without adding visible labels. It uses muted ink and the shared Button's hover and focus tokens, stays visible without hover, and introduces no animation.

The Copy chat button copies the entire saved conversation as Markdown, including messages outside the currently loaded page, speaker names, local dates/times, source links, system events, and proposal status. In-progress replies are copied as a snapshot and marked incomplete. It sits with Files in normal headers and at the right of the Conversation pane header while editing a document. Compact task headers use a top toolbar for Conversation, Files, New document, icon-only Copy chat and Fullscreen. Task properties sit below the title in a collapsed Task options disclosure: labels, Today, priority, snooze and repeat. Native disclosure controls support Tab and Enter/Space, visible focus, and wrapped content in narrow panes. Repeat uses an icon when unset and shows the schedule when configured. Controls use small ghost Buttons with accessible names and tooltips; the Conversation link has an explicit accessible name. The editable title wraps naturally below the toolbar. Conversation actions remain above the title; task properties wrap within the disclosure below it. Stop and Mark reviewed remain visible alongside the disclosure. Notes use a keyboard-accessible disclosure with a one-line preview (or Add context when empty); opening it reveals the existing textarea and blur-to-save behavior. The latest three documents use a single title line; full paths and modified dates remain in the file picker. No saved notes or metadata are removed. The redundant Ready for review badge is omitted from task details. Thread headers keep Files and Copy chat inline and wrap them below the title when space is tight. The button uses the shared ghost Button, shows Copying / Copied / Retry copy feedback, announces success or failure without moving focus, and is disabled for empty or initially loading conversations. It never copies an unsent composer draft or document contents.

While the thread is busy, a persistent “Working…” status sits above the composer, outside the scrolling message list. It remains visible after partial replies and during silent reasoning or tool use, in both full conversations and compact task details. It disappears when the run finishes, fails, or stops. The status uses muted text and lime-strong dots, announces itself with `role="status"`, and never moves keyboard focus. Decorative dots stop animating with reduced motion; the text remains visible.

Skill revisions render as `SkillChangeCard` in group/private conversations and compact task chats. The card names the skill, shows the reason and current saved status, and offers Review changes / Discard while pending. Review expands a shared `PackageDiff` with labeled Before and Proposed contents for every changed file; Apply revision appears only after opening the comparison. Stale proposals explain how to merge in Manage skills. Applied and discarded cards remain in history with reviewable contents. Status refreshes after changes in Settings, and loading, missing-proposal, and retryable failure states are explicit. Buttons disable during actions, retain keyboard focus indicators, and use the existing Fragments primitives. Surface, line, ink and muted tokens define the card. Comparisons stack vertically within the narrow chat column; long paths wrap and file contents scroll. No animation is introduced.

### Composer

A two-line textarea that grows with content, with a lime send button that is muted while empty. `↵` sends and `⇧↵` adds a line. Typing `@` opens the mention picker, with routines listed above agents; arrows move, `↵`/`Tab` insert, and `Esc` closes. In group/private chats, Escape leaves the message editor and focuses the selected thread in the middle list without clearing the draft; H/Left can then return to the sidebar. An open mention picker consumes the first Escape. Task chats retain Escape-to-task-list behavior, and an open document retains save-and-close priority. Stop appears while an agent in the thread is running.

Typing `/` at a word boundary opens the skill picker in full and compact composers. It searches names and descriptions, shows shared or agent-owned scope, and filters disabled, archived, broken, or incompatible skills against all current recipients (the lead by default, explicit @mentions otherwise). Enter/Tab selects; Escape dismisses even an empty picker without leaving the composer. Loading, retryable errors, and no matches are explicit. Choosing a skill adds a removable chip and preserves surrounding draft text. Sending loads its stable ID; failed sends restore chips with the draft, and changing recipients blocks sending incompatible selections. Runtime tool requirements remain authoritative. The picker uses surface, line, lime-soft, ink, and muted tokens, stays within the compact pane, scrolls long results, and announces active options without moving textarea focus.

### Document workspace

`ThreadView` opens local Markdown links and document rows directly into a spacious editor in both group conversations and task details. Opening hides the sidebar and task/thread list. There is one 56 px draggable window header with **Back to list**, **Chat** on the left beside Back, document title, save state, **Outline and notes**, and visible icon buttons for **Copy document**, **Insert image**, and **Typewriter mode**. Reserve its first 104 px for native macOS controls; exclude interactive controls from dragging. Titles truncate with the full path in a tooltip. A single file has a passive title; multiple files make the title a **Switch document** button opening the searchable picker. Do not add a tab strip or require an intermediate split/focus step.

Chat and outline start hidden and remember the user's choice locally. Chat appears on the left without remounting the composer or document, preserving drafts, selection and undo history. Its divider stays available in compact windows and supports pointer and keyboard resizing down to a 24 px sliver on either side. Chat keeps a 320 px content width and the editor viewport keeps 360 px; their visible areas clip below those widths so the editor can cover the chat without crushing its contents. Focusing content in a clipped pane expands it to a usable width. Left/Right adjust chat by 10 px (Shift by 50), Home/End go to the limits, and Enter or double-click restores the default 36% split. Chat width is remembered locally; narrowing the window clamps the visible split without overwriting the saved preference. The document remains usable at the app's 900 px minimum width. Back saves before restoring the same selected task/list or conversation and its draft. Switching files saves first; failure keeps the current document and its edits open. Each document restores its caret and scroll position. The header and panes use glass, canvas, line, ink and muted tokens without new animation.

The document is always formatted and directly editable. While the caret is in a heading, muted monospace `#` markers in the left margin indicate its level without becoming editable content or changing Markdown. Backspace at the start of a heading removes one `#` level; removing the last level turns it into a paragraph. This preserves the preceding paragraph, text formatting and caret position, and supports undo. Backspace within text and deletion of a selected range keep their ordinary behavior. The prose gutter reserves space for all six levels. There is no source toggle, draft/byline header, or suggestions card. The header contains the document title, save state, and Back action. Surface/canvas, ink/muted, and line tokens define the editor; lime-soft highlights text selection and referenced passages. Editing uses native undo, Markdown input shortcuts, and Cmd+B / Cmd+I. Headings, lists, code, quotes, tables, images, and checklists serialize back to Markdown; formatting syntax can normalize on edit. HTML, frontmatter, and footnotes are currently read only to avoid dropping unsupported content.

Type `/` on an otherwise empty paragraph to open the formatting insertion menu. Search narrows tables, links, images, bullet/numbered lists, checklists, quotes, code blocks, and dividers. Arrow keys choose; Enter/Tab inserts; Escape dismisses before the document closes. The menu stays near the caret inside the pane, scrolls within its height limit, and uses surface, line, lime-soft selection, and muted descriptions. Code blocks and read-only documents do not offer commands. Table insertion starts with three columns and three rows, including a header, and retains the existing table controls. Link insertion opens a labeled Text/Destination form; Cmd+K uses the current selection as link text. Cancel preserves document content; invalid destinations or a changed document retain the form with an error. These actions use normal editor undo and autosave, with no animation.

The toolbar’s **Insert image** action and `/image` open the same compact form for choosing local files or entering an image URL/relative path with alt text. Pasting clipboard images and dropping image files insert at the selection or drop position. PNG, JPEG, GIF, WebP and AVIF files are accepted up to 10 MB each, with up to ten files per import. Local imports are copied into a uniquely named file in a `<document>.assets` folder beside the Markdown file, and serialized as portable relative links. Existing local images resolve relative to the document, within its workspace and without following symlinks; HTTP(S) images load directly without a referrer. Undo removes the inserted nodes while retaining asset files for redo. Typing during an import preserves intervening edits and tracks the insertion position. Failed imports show a dismissible alert or keep the form open; cancel leaves content unchanged. Read-only documents display images but disable insertion.

Images fit the prose width and preserve their aspect ratio. Loading and failed images use a muted, dashed placeholder; failures retain their source and alt text and offer **Retry image**. Selected images show the focus outline. The insertion form uses the existing surface, line, ink, muted and focus tokens, supports Escape, restores editor focus when closed, and scrolls within short panes. Image insertion adds no animation.

`DocumentFileLabel` is shared by task preview rows and `DocumentPicker`: file icon, readable filename, exact relative path, and a quiet modified date with a full timestamp tooltip. Names and paths wrap without displacing trailing controls. Files are sorted by modification time, newest first, with path as a stable tie-breaker. Use these rows for choosing a document, not large cards or inline document bodies.

`DocumentPicker` is a focus-trapped modal opened by Files, View all, or the editor title. It contains a search field and scrollable file list, with explicit loading, empty, no-match and retryable failure states. Search matches name and path. Arrow keys move through file choices; Enter in search opens the first result. Each row has a separate Show in Finder action and the current document has a visible check. Escape/outside click dismisses and returns focus to the appropriate trigger; opening disables dismissal until save/read completes. Save or read failure remains visible without dropping edits. Finder actions retain workspace path and symlink restrictions. Surface, line, ink, muted, focus and lime-soft tokens match the other pickers; the modal fits short and compact windows.

The toolbar exposes **Copy document**, **Insert image**, and **Typewriter mode** as individual icon buttons with accessible labels and tooltips, alongside **Outline and notes**. These actions remain directly available in compact windows; the title truncates to make room. Copy includes the full current Markdown source, including unsaved or recovered edits and read-only contents, without changing selection or saving. The status area announces success or failure. Typewriter exposes a pressed state using lime-soft/lime-ink. Chat and outline are independent header toggles with accessible names and states.

Typewriter mode centers the visual caret line after typing or moving a collapsed selection, including wrapped paragraphs. Half a viewport of breathing room at each end permits centering the first and last lines. It adapts to pane resizing and content reflow. Manual scrolling remains free until editing resumes; selecting a passage does not move the viewport. Canvas gradients fade the top and bottom 72 px (at most 15% of the writing viewport), leaving toolbars, alerts, popovers and pointer interaction unaffected. Centering is immediate, with no animated scrolling, including reduced-motion mode. Typewriter is unavailable for read-only Markdown. Typewriter mode is local to the open document and does not change its saved content.

Typing two consecutive hyphens (`--`) in prose replaces them with an em dash (`—`). Immediate Backspace reverses the substitution so literal double hyphens remain available. Inline code, code blocks and editable link source keep literal hyphens; opening or pasting existing Markdown does not run this substitution. The resulting text participates in ordinary undo, autosave and Copy. Use the `/` formatting menu to insert a divider.

#### Floating outline and scratchpad

`DocumentCompanion` is a floating glass card at the left of the document's writing viewport, available with or without chat. The **Outline and notes** header button shows or hides it; its expanded state and panel name are accessible. The card stays in place while prose scrolls, independently scrolls long contents, and sits above typewriter fades. At editor widths of 760 px or more, a reserved left gutter keeps it clear of the text. The card starts hidden and remembers the user’s preference; smaller panes show it as a dismissible overlay without changing that preference on resize. Choosing a heading in an overlay closes the card and focuses the destination. A close button returns focus to the header toggle. The card is at most 420 px high (340 px in narrow panes), bounded by available viewport height.

A shared `ToggleGroup` at the top switches **Contents / Scratchpad**, with a lime-soft selection pill that slides for 160 ms; reduced-motion mode removes that transition. Arrow keys move between modes without invoking workspace navigation. Contents lists live H1–H6 headings with their level, indentation and wrapped labels, including unsaved changes and external reloads. Duplicate titles navigate by document position. The current section has a visible selection marker and `aria-current`; clicking a heading moves the caret and scrolls it into view, centering it when typewriter mode is enabled.
